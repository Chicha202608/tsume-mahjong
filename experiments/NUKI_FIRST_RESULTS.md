# 北抜き優先探索の検証

2026-10-21、seed 20261021、実際の108枚から取り出した配牌で測定。
配牌は一〜九筒・二索・三索・五索・北。最初のツモを五索、山の末尾を一索・北とし、連続北抜きを含める。
変更前の `openSearch.ts` を一時コピーして比較し、比較後にコピーを削除した。

## 短い山（10枚、両方とも時間切れなし）

| 項目 | 変更前の混合探索 | 北抜き優先＋後続の混合探索 |
| --- | ---: | ---: |
| 最終得点 | 18,000点 | 18,000点 |
| 手牌候補の列挙数 | 129 | 21＋129 |
| 実際に手順を再生した回数 | 129 | 4＋16＝20 |
| 到達不能で除外した候補 | 0 | 17＋113 |
| 実測時間（単回） | 130 ms | 12＋34＝46 ms |

手順再生は約84.5%減った。候補の総列挙数を減らすだけでなく、北抜きの経路をまとめて列挙し、到達できない候補の再生を省く効果を確認した。
北抜き優先の段階では16,000点が得られ、後続探索で18,000点に更新された。最初の改善結果は約3 msで返された。
これは1局面の測定であり、全局面で同じ時間短縮を保証するものではない。

## 通常の山（55枚）

各探索段階を3秒に制限して確認。北抜き優先で16,000点、その後の混合探索で18,000点。変更前の混合探索も18,000点だった。
時間制限に達しているため、この結果から探索完了までの時間を比較していない。
全ての出力手順を実際の状態遷移で再生し、和了と再採点の一致を確認した。

短い山ではseed 17・771・2026・81・129でも変更前後を比較し、変更後の最終得点が下がらないことを確認した。

## 継続検証

`node node_modules/vitest/vitest.mjs run --config experiments/vitest.config.ts experiments/nukiFirst.bench.ts`

現在の北抜き優先探索と後続探索の処理数・得点・時間を再測定する。変更前の測定値は上記の記録を参照。
